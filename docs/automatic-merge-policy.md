# 自动更新与自动合并边界

同一 catalog 内，同一上游仓库、同一目标提交的可准备更新合成一个稳定命名的批次 PR。已退休／人工维护资源及已在目标版本的资源不混入。共享依赖的检查失败仍阻断整个依赖组；不同目标版本不强行合批。批次成员变化可以复用原 PR，但人工提交、标题或正文修改仍受原有保护。人工关闭的同一目标版本批次不会因为成员变化而重建。

合批只减少 PR 数量，不批准技能行为变化。当前自动合并仅允许机器人提交的非草稿、仅修改已登记 marketplace 生成文件的 PR，且内容必须等于可信主分支 catalog 和生成器计算的结果。完整提交上的 Tooling tests 与 claudespace/fixed-sources 必须成功，仍遵守 main 分支保护及最新基线要求；不会使用管理员绕过。

catalog pin、技能 Markdown、运行时、hooks、权限、工作流和适配记录都不在自动合并白名单。内部发布的版本同步需要上游可验证 CI／发布证明后再单独扩展，不能因为同属本人仓库便自动批准代码更新。草稿和人工 PR 始终保留审查。
