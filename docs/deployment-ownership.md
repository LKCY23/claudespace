# 资源来源、部署归属与交接

Claudespace 维护可审阅的固定来源和宿主适配；不扫描本机目录来决定安装，也不保存部署状态、凭据、原生账号或会话。

## 来源和安装路径

| 层 | 职责 |
| --- | --- |
| Claudespace catalog 与固定提交 | 正文、来源、适配、依赖、支持的选项 |
| claude-config-data 的 Agent/App Profile | 资源选择、启停和可移植运行配置；机器选择文件指定采用的 Profile |
| 本机 Machine | 程序、配置根、安装路径、依赖与仓库选择引用 |
| claude-config | 检查来源和部署差异、所有权交接、事务写入及恢复 |
| 本机 managed state | 上次部署的实际指纹与归属；不提交到资源仓库 |

Claude 独立技能位于绑定的 `config_root/skills`；Codex 位于 Machine 明确绑定的 `.agents/skills`。两个客户端可采用同一来源，部署副本和原生控制各自维护。一个客户端的正规副本不是另一个客户端的重复入口。

## 单一部署者

对已经纳入框架的客户端／技能组合，由 claude-config 写入。CC Switch 等工具继续处理其被授权的其他职责，但须退出相同组合的安装与同步声明。交接精确到客户端；不能按全局技能名称关闭另一个客户端独有的入口。

claude-config 0.6.0 的 plan / doctor 可识别重叠 CC Switch 声明与同名 Codex 旧入口；这里只提供协作式约束，不能阻止任意外部程序修改文件。后续外部变化仍通过指纹和事务保护发现。

## 生命周期与验收

- 停用保留正文；移除选择保留 residual。删除需明确退役，首版仅支持归属准确、内容未变化的独立技能。
- 来源变更先更新 Claudespace 固定版本，再明确采用和部署；本机修改不自动变成来源或新基线。
- 盘点记录已选来源、路径、管理者、正文／权限／缺失差异和原生启停。文件存在不能证明原生发现。
- 原生发现可使用隔离客户端元数据接口验证，不执行技能业务或发送模型任务；当前已经运行的会话仍可能需要重载。
- 系统、插件和独有未接管技能保留；未知文件、后续手改及共享归属必须在退役前处理。

工具的具体命令、错误码及恢复契约由 claude-config 的 `references/deployment-consistency.md` 维护；部署机的实际验收及决策写入私有配置仓库，避免把本机状态混入公共来源定义。
